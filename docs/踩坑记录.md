## 详细复盘（面试口述版）

面试不会让你念表格，会问"讲一个你踩过的坑"。下面三段能讲 2–3 分钟，**用自己的话再改一遍**。

### 坑 1：为了省 C 盘空间，把整个 IDE 搞挂了

ESP32 支持包要 8.57 GB，我 C 盘紧张，就把 Arduino 的数据目录 `Arduino15` 做成目录联接（Junction）指向 D 盘。装包一切正常，8.57 GB 也确实落在 D 盘，但装完之后 `Tools → Board` 是空的，连 Arduino Uno 都没有。

我先怀疑界面缓存，重启、`Reload Board Data` 都试过；又怀疑包没装完，去查目录，`boards.txt` 和 8.57 GB 都在，排除。最后绕过 IDE，直接调它底层的 `arduino-cli board listall`，拿到 IDE 没显示的原始报错：`following symlink ... The system cannot find the path specified`。

结论：arduino-cli 不跟随符号链接，硬件平台加载失败。改成用环境变量 `ARDUINO_DIRECTORIES_DATA` 指向 D 盘就好了——效果一样（数据仍在 D 盘），但不经过联接。

**能讲的点**：IDE 的界面报错经常没有信息量，要能绕过界面直接调底层命令行。

### 坑 2：实测数据推翻了我自己的设计

我按手册把"过冷告警"定成低于 20℃ 持续 5 分钟、全天生效。接上传感器第一次实测：19.4℃、46%——规则当场成立。

如果那天直接开跑 7 天，我会收到一整周的"过冷告警"，而其实只是 11 月的自然室温。问题在于我把两个场景混成了同一条规则：夜里的 19℃ 是"空调温度设太低忘关"，白天的 19℃ 只是"天气冷"。

改法是：过冷只在夜间 22:30–07:00 判定，白天偏冷交给舒适度提示（低于 22℃ 就提示值班老师调空调，不 @人）。过热和潮湿仍全天，因为设备柜积热、结露白天夜里都会发生。

**能讲的点**：阈值不是拍脑袋定的，是拿实测数据反过来修的；同一指标在不同时段语义完全不同，不能一刀切。

### 坑 3：接线只认丝印，不认经验

DHT22 模块的针脚丝印是 `GND NC DAT VCC`。我凭"常见模块 VCC 在前"的经验接了，串口每两秒一行 `read failed`。按丝印逐个核对后重接，一次读通。

**能讲的点**：`read failed` 这种"全空"的错误，先怀疑接线再怀疑代码——因为代码能跑到打印这一步，说明编译、烧录、串口都是好的。

### 坑 4：WiFi 一断就再也回不来

热点关掉再打开，板子一直在刷 `[WiFi] lost, reconnect`，重开热点四分钟都连不回来，缓冲一路涨到 26 条。

我先把能想到的都排了：热点是不是没起来（电脑能连上，排除）、MQTT 重连逻辑是不是坏了（日志显示卡在 WiFi 那一步，根本没走到 MQTT）。最后定位到 `WiFi.reconnect()`——它在 AP 短暂消失后可能不会重置状态机，而且我是**每 loop 都调一次**，等于持续打断它。

改成 `WiFi.disconnect()` → 等 100ms → `WiFi.begin(SSID, PASS)`，并且用 `lastWifiTry` 限流到每 10 秒一次。改完之后，重开热点 2 秒内自动连回，缓冲 6 条一次补完、归零。

**能讲的点**：库/框架里"看起来应该管用"的 API（`reconnect()`）可能只是薄封装，真出问题时要用底层那对 `disconnect` + `begin`；另外**重连这类操作一定要限流**，不然它自己会把状态机搞乱。
