## 第 4 项补充：后端离线期间的消息有没有丢（比指标本身更能说明问题）

场景：后端订阅进程**完全停止** → 从 EMQX WebSocket 客户端连发 3 条 QoS1 消息 → 重新启动后端。

| 观测点 | 结果 |
|---|---|
| 重启后是否立刻收到离线期间的 3 条 | ✅ 是，`a-002 / a-003 / a-004` 在 `[connect]` 之后**立即连续**打印，无需再发 |
| 到达顺序 | ✅ 按发送顺序 002 → 003 → 004，未乱序 |
| 依赖的机制 | 固定 `client_id="server-sub"` + `clean_session=False`，broker 为离线会话保留队列 |
| 反证 | 若用 `clean_session=True`，这 3 条会永久消失（设备已收到 PUBACK，不会重发） |

> 这条不是手册里的验收项，是**自己加的一条**——因为"设备侧补传"只覆盖"设备断网"，
> 覆盖不了"后端重启"。面试讲可靠性时，这两层能一起说。
