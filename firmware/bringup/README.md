# bring-up 记录（阶段 1）

这里是**从"板子能亮"到"三个传感器同时读通"**的全过程程序，按顺序排列。
保留它们的意义：证明硬件是**一步步验证上来的**，不是一次接好碰巧成功。

| 文件 | 验证什么 | 结论 | 日期 |
|---|---|---|---|
| `01_selfcheck` | 烧录链路 / 串口 / GPIO 输出 | 串口 `tick: LED on/off` 稳定，板载灯闪 | 11-18 |
| `02_dht22` | 单总线传感器 DHT22 | `T=19.40 C  H=45.50 %`，读数稳定 | 11-18 |
| `03_bh1750` | I2C 总线 + BH1750 | 扫描到 `0x23`；白天朝窗 41 662.9 lux，遮住 1.7 lux | 11-19 |
| `04_merged` | 三个测量值合并 | `{"t":17.4,"h":40.3,"lux":211.7}` 同一条输出里 | 11-19 |

## 关键结论（写 README / 面试用）

1. **数值不是绝对值，安装位置决定它**：同一块 BH1750，朝窗 41 662.9 lux，被手掌遮住 1.7 lux，放在桌上朝暗处 30–50 lux。
   所以"夜间判灯阈值 100 lux"必须结合安装位置来定，换个位置阈值就失效。
2. **先验证协议/总线，再写业务**：I2C 先扫描（`0x23` 出现了才写读取逻辑）；
   MQTT 先用 WebSocket 客户端验证主题（`iot/+/data` 收到才写订阅）。
3. **数据格式先离线调对，再上网络**：`04_merged` 直接输出 JSON，
   等于提前把 MQTT payload 的格式定死了。

## 接线（2026-11-19 定稿）

| 信号 | 板子针脚 | 说明 |
|---|---|---|
| DHT22 VCC / GND | 3V3 / GND | 经面包板电源轨共用 |
| DHT22 DAT | **D4**（左排第 7 针） | 单总线，模块 NC 针空着 |
| BH1750 VCC / GND | 3V3 / GND | 与 DHT22 共用电源轨 |
| BH1750 SDA | **D21**（左排第 14 针） | I2C |
| BH1750 SCL | **D22**（左排第 17 针） | I2C |
| BH1750 ADDR | 悬空 | 默认地址 0x23 |

引脚位置按 **NodeMCU-32S（38 针）** 的实际丝印数：3V3 在右排第 19 针（天线端最上），
GND 在右排第 6 针，D4/D21/D22 在左排第 7/14/17 针（从 USB 端数第 1 针）。

接线图见 `docs/img/接线_DHT22.png`、`docs/img/接线_BH1750.png`。
